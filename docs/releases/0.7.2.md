### 中文

#### 插件音源（实验性）

- 新增 Plugin API v1 动态音源：通过系统文件选择器导入有界插件包，校验 Manifest、版本、签名与权限，安装后默认禁用；启用前展示能力与权限变更，升级失败保留旧版本。
- 每个插件运行在独立 QuickJS 运行时与独立进程服务中，脚本调用、回调和销毁串行执行；HTTP 请求按精确域名与公共 DNS 限制，重定向、响应体大小和超时均有上限，不继承应用账号 Cookie。
- 插件账号凭据存入 Keystore 加密保管库，按账号与策略隔离；支持 API Token 以及公开客户端 OAuth2/PKCE，回调地址严格校验。
- 已贯通搜索、播放、歌词、歌单、专辑、歌手、榜单、首页、资料库、收藏、下载与认证共 12 项能力，动态音源会出现在主搜索、来源筛选、首页、资料库及歌曲菜单中；提供 SDK、CLI、示例插件与开发文档。
- **当前为 RC 工程预览，不是稳定版验收结论。** API 35 转译模拟器已有核心链路与播放子集证据；API 24、完整 UI/OAuth/后台流程、真实第三方服务与实体真机仍待验收。第三方源由插件作者维护，弥乐不保证任何外部服务可用。

#### 后台页面恢复

- 扩展 Activity 被系统销毁重建后的状态恢复：首页与发现的歌单/榜单、搜索结果与详情、音乐库子页、播客、下载、云盘、私信、插件目录及全屏播放器会恢复原页面、滚动位置与已加载内容，不再统一退回首页。
- 详情页导航栈使用稳定标识保存与恢复，嵌套工具页（例如「播客 → 某档节目」）返回后仍停留在原层级。
- 已加载数据在进程内复用，仅为保存状态写入短标识，避免把大型歌单塞进系统 Bundle；进程真正退出后仍按正常加载流程重新请求，不做持久化假恢复。
- 修复每日推荐/热榜第二次打开或页面重建后只剩封面与歌曲数、列表为空的问题：已传入的歌曲列表不再被“本进程只刷新一次”的网络闸门拦截。
- 统一新旧音源选择记录的读取优先级，避免回到前台时意外切换音源并清空当前页面。

#### 首页与界面

- 首页快捷入口改为每页两张半宽卡片，左侧正常留白、右侧保留 44dp 下一组露出，松手磁吸到整页。
- 移除主页卡片的矩形按压高光，统一封面卡为跟随圆角的柔和阴影。
- 存储设置新增播放缓存上限（256MB / 512MB / 1GB / 2GB），达到上限按 LRU 清理最旧缓存；设置修改后下次启动生效。
- 设置页下拉箭头间距收紧，服务页移除冗余灰色描述。

#### 歌单与播放

- 歌单详情改为渐进加载：先显示歌单摘要与前 100 首，剩余歌曲按 100 首并行补齐，大歌单不再长时间只显示转圈。
- 打开中的网易云歌单在进程被回收后可在 30 分钟内自动恢复，并复用歌单缓存；显式返回会清除恢复记录。
- 播放器支持点按封面切换歌词页、左右滑动封面切换歌曲；歌词跳转后重新锚定当前行，浏览歌词时不再被自动滚动抢回。
- 上一首遵循“当前播放超过 5 秒则重播当前曲目”的设置；同时拦截系统默认上一首行为，避免执行两次。
- 修复部分 Qualcomm 设备平台 FLAC 解码异常：按机型与错误特征启用软件或 FFmpeg 回退，并补充回归测试。

#### 一起听与歌词

- 一起听新增「单人模式」：房间保持在线，心跳与房间状态继续维持；本机可独立切歌、暂停、拖动进度，不会向对方发送指令；关闭后同步回房间当前播放。
- 新增「设置 → 歌词 → QQ 音乐：括号歌词识别为伴唱」（默认关闭）：整行括号内容会挂到上一句主歌词，从主歌词结束时开始，结束时间沿用括号行原本的结束时间；逐行处理并保留原顺序。
- 括号识别对下载歌词同样生效，并支持 AMLL 等来源的伴唱括号；只改写“整行成对括号”的行，避免误伤普通歌词。

#### 登录与 i18n

- 修复 YouTube Music 登录白屏：WebView 在加载过程中被 Compose 释放会带崩共享渲染进程；改为在 `onRelease` 中销毁，并补充网络/VPN 错误提示与重试按钮。
- 修复汽水音乐扫码登录：上游旧二维码指向已 404 的 `ucenter_web/app/sdk-next`；现在从 `light/invoke/scan_login` 获取有效二维码，并提示使用汽水音乐手机客户端扫码。
- 补齐简体中文、繁体中文、日文翻译，覆盖全部 1560 个资源 key 并通过占位符校验；土耳其语缺失条目回退英文；汽水扫码与 YouTube 登录文案改为资源字符串。

#### 副屏伴侣（可选，实验性）

- 「设置 → 测试功能尝鲜」新增实验性 MeloX Rear 副屏伴侣入口，用于在支持的副屏设备上控制播放。
- 该应用是来自上游 YTRear 的独立工程，不随本版本 APK 分发；沿用上游 `com.luna.music` 包名，可能与汽水音乐冲突，并会暂缓所选播放器的媒体通知。上游未声明许可证，授权确认前不发布该副本，实际副屏兼容性仍待真机验证。

#### 已知限制

- 插件音源为 RC 工程预览：API 24、完整 UI/OAuth/后台流程及实体真机验收尚未完成；第三方服务可能失效、限流或返回不可播放地址。
- 页面恢复已覆盖主要入口，但系统彻底结束进程后只按正常冷启动流程重建，不承诺恢复所有临时子页面。
- 实验性 USB 独占仍只支持 UAC1 与 PCM16 解码输出（24/32 位容器为补零转换），UAC2、异步反馈与 DSD 未支持。
- 本次 JVM 回归为 535 项通过、0 失败、3 项既有跳过；真实设备与第三方服务验收仍以实际结果为准。

### English

#### Plugin sources (experimental)

- Added Plugin API v1 dynamic sources: bounded packages are imported through the system file picker, with Manifest, version, signature and permission validation. Packages install disabled by default; capability and permission changes are shown before enabling, and a failed update keeps the previous package.
- Each plugin runs in an isolated QuickJS runtime and worker process. Script creation, calls, callbacks and destruction are serialised; HTTP is restricted to exact hosts and public DNS with redirect, body-size and timeout limits, and never inherits account cookies.
- Plugin credentials live in a Keystore-backed vault isolated per account and policy. API tokens and public-client OAuth2/PKCE are supported, with strict callback validation.
- All 12 capabilities are wired: search, playback, lyrics, playlists, albums, artists, rankings, home feed, user library, favorites, download and authentication. Dynamic sources appear in main search, source filters, home, library and song menus; an SDK, CLI, examples and docs are included.
- **This is an RC engineering preview, not a stable acceptance claim.** An API 35 translated emulator has core-chain and playback subset evidence; API 24, complete UI/OAuth/background flows, real third-party services and physical devices remain unverified. Plugins are maintained by their authors; MeloX cannot guarantee any external service.

#### Background page restoration

- Extended restoration after the system destroys a stopped Activity: home/explore collections and charts, search results and details, library subpages, podcasts, downloads, cloud drive, messages, plugin catalog and the full-screen player recover the page, scroll position and loaded content instead of falling back to the home root.
- The detail navigation stack is saved and restored with stable identifiers, so nested tool pages (for example Podcasts → a show) return to the same level.
- Loaded data is reused process-locally and only a short token enters the system Bundle; large playlists are never stuffed into instance state. A real process exit still follows the normal loading path, and this is not claimed as persistence across process death.
- Fixed daily recommendations/charts reopening or rebuilding with only the cover and count: supplied song lists are no longer blocked by the process-wide "refresh once" gate.
- Unified the old and new source-selection records so returning to the foreground cannot silently switch providers and clear the current page.

#### Home and interface

- Home quick actions now show two half-width cards per page, left-aligned with a 44dp peek of the next pair and magnetic snapping.
- Removed the rectangular press ripple from home cards and unified cover cards on rounded, soft shadows.
- Added a playback cache limit (256MB / 512MB / 1GB / 2GB) under Storage, with LRU eviction and application on the next launch.
- Tightened dropdown chevron spacing in Settings and removed redundant grey descriptions from service pages.

#### Playlists and playback

- Playlist details load progressively: summary and the first 100 tracks appear immediately, then the remaining tracks fill in parallel batches of 100; large playlists no longer sit on a spinner.
- An open NetEase playlist can be restored within 30 minutes after process reclamation, reusing the playlist cache; an explicit Back clears the restore record.
- Tap artwork to switch to lyrics and swipe artwork left/right to change tracks. Lyrics re-anchor after a seek, and manual lyric browsing is no longer pulled back automatically.
- Previous follows the “restart after 5 seconds” setting, including intercepting Media3's default previous command so it never runs twice.
- Fixed platform FLAC decoder failures on some Qualcomm devices with a model/error-gated software or FFmpeg fallback and regression coverage.

#### Listen Together and lyrics

- Added Listen Together solo mode: the room stays online with heartbeats and room state; local play/pause/skip/seek never sends commands to the other listener, and disabling solo syncs back to the room's current playback.
- Added Settings → Lyrics → “QQ Music: bracket lines as backing vocals” (off by default). A fully parenthesized line joins the previous lead line from its end while keeping its original end time, processed sequentially.
- The bracket transform also applies to downloaded lyrics and AMLL-style accompaniment brackets; only lines wrapped entirely in a matching bracket pair are rewritten.

#### Sign-in and i18n

- Fixed the blank YouTube Music sign-in page: releasing a still-loading WebView from Compose could crash the shared renderer. The view is now destroyed in `onRelease`, with network/VPN errors and a retry action.
- Fixed Qishui QR sign-in: the legacy upstream QR pointed at the retired `ucenter_web/app/sdk-next` page. The app now obtains a live `light/invoke/scan_login` QR and asks the user to scan with the Qishui app.
- Completed Simplified Chinese, Traditional Chinese and Japanese translations for all 1,560 resource keys with placeholder validation; Turkish falls back to English where missing. Qishui and YouTube sign-in strings are now resources.

#### Rear companion (optional, experimental)

- Added an experimental MeloX Rear companion entry under Settings → Experimental for controlling playback on supported rear displays.
- The companion is a separate YTRear-derived project and is not distributed with this APK. It reuses the upstream `com.luna.music` package (which can conflict with Qishui) and defers the selected player's media notification. The upstream license is unspecified, so the fork is not published until authorization is confirmed; real rear-display compatibility remains unverified.

#### Known limitations

- Plugin sources are an RC preview: API 24, complete UI/OAuth/background flows and physical-device acceptance remain pending, and third-party services may fail, rate-limit or return unplayable URLs.
- Page restoration covers the main entry points; after a real process kill the app follows the normal cold-start path and does not promise every transient subpage.
- Experimental USB exclusive output remains UAC1/PCM16 (24/32-bit containers are zero-padded); UAC2, asynchronous feedback and DSD are unsupported.
- JVM regression for this release: 535 passed, 0 failed, 3 pre-existing skips. Real-device and third-party-service acceptance still depends on actual results.
