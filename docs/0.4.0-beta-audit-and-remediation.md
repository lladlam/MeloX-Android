# MeloX Android 0.4.0-Beta 审计与修复计划

[English](../README.en.md)

本文档记录 2026-08-20 对 MeloX Android、Mei Android 与 MeloX iOS 的源码对比结果，并作为 `0.4.0-Beta` 的实施清单、阶段验收标准和发布依据。

## 审计范围

- MeloX Android：当前 `main` 工作树，审计起点 `a29c7d1`，包含审计开始前尚未提交的播放器过渡与歌词设置改动。
- Mei Android：`/home/lladlam/项目/Mei_MeloX_Android`，审计时 `main@a523679`。
- MeloX iOS：`/home/lladlam/项目/MeloX` 当前 `main`。
- 视觉佐证：仓库 `.adb_compare/` 中 2026-08-15 的真机截图；源码为最终判断依据，旧截图不用于否定之后新增的实现。
- Figma 不在本次证据范围内：此前只确认浏览器读取超时，没有成功读取完整设计文件。

## 判断原则

1. 不把平台差异机械判定为缺失。iOS Live Activity、Dynamic Island 与 PiP 歌词在 Android 上允许分别映射为 Media3/HyperOS 通知和悬浮窗。
2. 不为不同音乐服务复制 UI。Provider 负责数据和能力，MeloX 负责统一的页面、动效和组件。
3. 静态代码可确认工作量或错误路径；FPS、功耗、温升和 ANR 风险必须由 Macrobenchmark、JankStats 或 Perfetto 验证。
4. 每个阶段必须通过单元测试和 Debug 构建后提交；发布阶段必须额外通过 Release 构建、签名验证和 APK 安装包校验。

## 已确认优势

MeloX Android 的功能总量并不落后：四音乐源、统一搜索、AutoMix、Apple/EVA/TextPV/Skyline 歌词、听歌识曲、评论/私信、HyperOS Focus、Lyricon、悬浮歌词和底层 Backdrop 均已存在。0.4.0-Beta 的目标是收敛碎片化实现、补齐业务闭环、减少后台与渲染成本，并建立可复现的性能门禁。

## 问题清单

### A. 高风险性能与稳定性

- [x] **PERF-01 默认动态背景触发整曲重复解码。** Balanced/High 下，播放服务为视觉背景再次用 `MediaExtractor + MediaCodec` 解码最长 12 分钟的 HTTP 音频。视觉响应应使用播放器已有的轻量时间线/音频采样；整曲分析只保留给显式 AutoMix。
- [x] **PERF-02 非歌词页仍运行歌词帧钟。** Artwork、Lyrics、Queue 常驻组合时，隐藏歌词层仍加载歌词并以 30–120 Hz 更新。只在歌词页可见且播放器展开时激活帧钟，状态与渲染生命周期分离。
- [x] **PERF-03 播放服务固定 10 Hz 主线程轮询。** 无媒体或暂停时也持续唤醒并反复读取设置。改成事件驱动设置快照，并按播放/混音状态动态调度。
- [x] **PERF-04 一起听空房间每 3 秒轮询。** 未进入房间时不应维持高频网络请求和不必要的 MediaController；退房、登出和停止时释放资源。
- [x] **PERF-05 下载删除与全量 JSON 索引写在主线程。** 文件操作、目录扫描、JSON 编码和落盘迁移至 IO，使用快照、原子写与合并写入；持久数据迁移到 Room。
- [x] **PERF-06 Library JSON 编码发生在主线程且缓存无边界。** 编码与写盘整体迁移至 IO；增加 TTL、容量和清理策略。
- [x] **PERF-07 播放资源解析同步阻塞。** 为即将播放的条目预解析并提供 single-flight；同步 Resolver 只消费缓存或执行受控兜底。
- [x] **PERF-08 OkHttp/Provider Registry 重复创建。** 建立 Application 级共享客户端和 Provider Registry；页面不再各自创建连接池。
- [x] **PERF-09 Media3 没有持久媒体缓存。** 增加有界 `SimpleCache + CacheDataSource`，供播放、seek、重播和分析复用。
- [x] **PERF-10 动态取色重复下载且缓存无限。** 复用统一网络/图片管线，缩略解码到约 160 px，改为有界 LRU，失败不永久缓存。
- [x] **PERF-11 AutoMix 分析缓存和锁表无限增长。** 完成后移除 key lock；分析结果使用有界内存缓存并支持持久化/清理。
- [x] **PERF-12 EVA/Skyline 逐帧写 Compose State。** 只有歌词行变化时更新组合状态；连续位移放进 draw/graphicsLayer，派生集合使用 `remember`。
- [x] **PERF-13 Apple 歌词逐字绘制调用过多。** 使用整行 mask/gradient 或 shaping run 合批，并限制有效刷新率。
- [x] **PERF-14 全屏模糊和玻璃层过重。** 暂停/后台停止动画；封面预缩放；避免换歌期间双套全屏 blur；长列表使用轻量材质。
- [x] **PERF-15 设置、消息与下载使用 eager 长列表。** 改用带稳定 key 的 LazyColumn 和分页/分段加载。
- [x] **PERF-16 持续识曲反复创建 WebView/WASM。** 一个持续识曲会话复用 runtime，停止时统一销毁。
- [x] **PERF-17 冷启动同步读取全部设置并建立多个控制链。** 首屏只加载主题/导航快照，其余延后；非必要集成按功能懒启动。

### B. 包体、构建与性能工程

- [x] **BUILD-01 Release 未启用 R8 与资源收缩。** 启用 `isMinifyEnabled`、`isShrinkResources` 和优化规则，并验证反射/序列化路径。
- [x] **BUILD-02 Material Symbols 字体约 15 MB。** 根据实际使用 glyph 子集化，或改为矢量资源；验证所有图标映射。
- [x] **BUILD-03 缺少项目级 Macrobenchmark/Baseline Profile。** 增加 benchmark 模块、Baseline Profile 生成器和冷启动/播放器/歌词/设置基准场景。
- [x] **BUILD-04 现有性能 Overlay 不可用且会扰动测量。** 修正包名、移除热路径分配和逐秒 flush，或由 JankStats/benchmark 替代；Debug 入口必须可达。
- [x] **BUILD-05 Gradle wrapper 未纳入版本控制。** 固定 Gradle/JDK 构建入口，并使本地和 CI 使用同一 wrapper。

### C. Mei 对标的业务与 UI 闭环

- [x] **MEI-01 缺少创建歌单。** 支持公开/私密歌单创建，并从“添加到歌单”页直接进入创建流程。
- [x] **MEI-02 缺少从自己的歌单移除歌曲。** 仅在具备所有权/写能力时显示，操作后刷新统一详情。
- [x] **MEI-03 本地音乐能力不足。** 下载继续保留可靠的 app-private 离线副本，同时可导出 MediaStore；提供按歌曲、艺术家、专辑和文件夹浏览。
- [x] **MEI-04 导航/返回栈碎片化。** 建立统一目的地与可恢复状态；根标签切换保留滚动位置和搜索状态，详情不再依赖多套局部布尔状态。
- [x] **MEI-05 非播放器页面缺少平板/横屏布局。** Home、Explore、Library、Search 和集合详情按窗口宽度自适应，关键页面提供双栏布局。
- [x] **MEI-06 高层玻璃组件不完整。** 补齐 Slider、Stepper、Bottom Search Toolbar、Context/Popup Menu、ActionSheet、Alert Field/Button、Modal/Sheet Surface 与 Color Picker，并统一使用 token。
- [x] **MEI-07 Home/Explore 内容层级单一。** 增加 hero、混合卡型、三行歌曲区块和服务端区块语义映射，保留空/错/加载状态。
- [x] **MEI-08 缺少可选 Classic 播放器外壳。** 提供 Apple/Classic 选择及 phone/tablet/immersive 横屏布局，不复制播放业务状态。
- [x] **MEI-09 国际化缺失。** 把用户可见文本迁移到资源，至少提供简体中文、繁体中文和英文基础覆盖。
- [x] **MEI-10 无障碍语义不完整。** 操作图标必须提供语义标签、Role、状态和足够触控尺寸；未知图标不得静默降级为错误语义。

### D. iOS 功能迁移深度

- [x] **IOS-01 集合详情入口不统一。** 首页、发现、搜索、账号、榜单和音乐库复用同一歌单/专辑/歌手/播客详情及单曲操作。
- [x] **IOS-02 TextPV 18 种风格名实不符。** 为每种模板提供独立构图、背景、排版和运动参数；不能继续把多种风格合并成同一背景与通用文字布局。
- [x] **IOS-03 下载缺少多选与逐次音质选择。** 支持下载全部前选音质、多选、全选/取消、选中歌曲下载和排行榜批量下载。
- [x] **IOS-04 页面放置与排序能力缩水。** 页面可以在首页、标签栏和音乐库中按能力放置与排序，并保持 Provider 无关。
- [x] **IOS-05 均衡器从 10 段缩水为 5 段。** 恢复 31 Hz–16 kHz 十段、±12 dB 连续调节和完整预设，同时按设备物理频段插值。
- [x] **IOS-06 设置搜索不可达。** 挂载现有搜索输入，支持标题、描述和关键词过滤，并保持返回状态。
- [x] **IOS-07 存储维护工具不足。** 增加分类统计/清理、缺失下载记录修复、孤立文件修复、缓存统计重置和数据库压缩。
- [x] **IOS-08 首页播客推荐丢失节目身份。** 保留 program ID 与播放歌曲，点击进入节目详情而不是父播客。
- [x] **IOS-09 通知歌词配置缩水。** 补标题/副标题模板、封面、正文、无歌词回退、前后台场景、暂停撤回和测试通知。
- [x] **IOS-10 识曲与私信入口过深。** 在主页面工具栏/快捷操作中提供真实入口，底层功能保持复用。
- [x] **IOS-11 更新日志与许可体验简化。** 提供内置更新日志、版本范围、重置推荐播放器设置和可浏览的项目许可。
- [x] **IOS-12 开发者性能入口缩水。** 提供可开关的 AutoMix/Beat 分析状态与诊断页，不在 Release 暴露敏感日志。

### E. 多音乐源自身未闭环

- [x] **PROVIDER-01 部分 Provider 缺少歌单、专辑、歌手或榜单详情能力。** UI 按 capability 隐藏不可用入口；已支持的平台必须实现统一详情，不再抛出“尚未实现”后才失败。
- [x] **PROVIDER-02 自动来源回退只有设置占位。** 要么实现明确授权的回退策略和来源提示，要么从可见设置中移除不可用项。
- [x] **PROVIDER-03 Provider 创建与 UI 状态重复。** 所有页面使用进程级 Registry 和统一 domain/capability，不创建 Provider 专属页面副本。

## 发布阻断条件

以下任一条件不满足时不得创建 Release：

- 单元测试、Lint 或 Release 构建失败；
- APK 未签名、签名证书与既有发布证书不一致，或 `apksigner verify` 失败；
- README/CHANGELOG/版本号/tag/APK 文件名不一致；
- 工作树仍含未审查、未提交或与发布无关的变更；
- GitHub Release 未包含签名 APK 或上传资产校验失败。
