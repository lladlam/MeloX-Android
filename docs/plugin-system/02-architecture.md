# 音乐源插件：架构决策与兼容计划

状态：**设计提案，未实现**。基线与代码证据见 [01-repository-audit.md](01-repository-audit.md)，本地 HEAD `ff87327`。设计与测试由 OpenAI GPT-6.1 Terra 基于本地源码及审计完成；未使用外部资料。此文中的接口、限制值和安全措施均为实施要求或候选值，不是现有保障。

## 目标与边界

插件仅适配音乐平台，返回标准搜索、资源、播放和歌词数据；宿主继续使用 `MusicProvider`、现有搜索 UI、Media3 播放队列、歌词和 AutoSync。内置源、账户和现有 LX 补源链保留；Apple Music 既有 MusicKit 特殊路径保留。不得绕过授权、付费限制或 DRM；不可播放、仅试听、需登录及订阅等状态如实传递，不把失败转成绕过权限的播放。应用正式 applicationId 和签名保持不变。下载、收藏、歌单、搜索、播放、歌词各自是可选能力，不能假定播放自动授权下载。

## 决策 1：来源身份和 API 演进

| 方案 | 结果 |
| --- | --- |
| `MusicSource` 增加单一 Plugin 枚举 | 不同插件冲突，卸载后无法还原身份，否决。 |
| 随安装生成枚举或只用显示名 | 枚举不可动态扩展，显示名不稳定，否决。 |
| 稳定的值类型 `SourceId`，内置值保持原文，插件独立命名空间 | 选择；改动身份边界但保留能力接口与 UI 模型。 |

引入可比较的字符串值类型，内置 storageValue 原样保留；插件统一 `plugin:<publisher-id>.<plugin-id>`，限小写 ASCII、长度及段格式，保留内置命名空间，安装时拒绝重复和大小写混淆。此名字只是身份标识，**不是发布者身份认证**；同 ID 升级必须满足包签名/用户信任策略，不能允许另一个包静默接管。卸载重装同身份才能重新关联，密钥轮换和冲突处理待定，禁止按名称或资源 ID 猜测关联。

逐步把 `MusicResourceId`、Provider key、歌曲/歌手/专辑引用及存储、来源选择、歌词绑定、下载和播放身份统一到 `(SourceId, opaqueResourceId)`；未知合法 ID 是独立值，不走 `fromStorageValue` 回退。保留兼容转换以处理仅内置源的特判，未知值显式 unavailable。旧数字网易云 mediaId、`melox://song/<Long>` 和现有内置 URI 必须原样可读；新增插件 URI 对 source 和 resource 分段严格编码、解码，禁止路径分隔符歧义和双重解码，定义版本与长度上限，mediaId 和 extras 一致验证。资源 ID 可含 Unicode、斜线、冒号及百分号；不得用未经编码的 `source:id` 直接切分。歌词、缓存、收藏和下载 key 同时包含两段，使用规范长度前缀或结构化编码，并明确迁移及碰撞测试。不能假设给枚举加转换函数即可覆盖所有 `when`、`entries` 和旧 UI 特判。

## 决策 2：持久化、卸载与降级

现有收藏、下载、选择、绑定、推荐及队列的具体损失见审计矩阵；不原地将插件记录写入旧格式。采用**版本化新存储与旧版隔离**：插件记录、未知扩展及插件来源选择放独立命名空间/文件，旧版本不读取或写入；内置记录先保留旧格式的读写兼容。新版本对可识别和未知记录都保留原始完整 payload（包括已知记录中的未知嵌套字段），修改单项时只替换目标项；不解析的记录按原始字节原样保存，排序/删除需显式基于稳定 ID，无法识别的项不能悄悄丢弃。数据大小、损坏条目和重复 ID 均应有可恢复的处理与限制，迁移原子提交并先保留备份，失败不删除原文件。

旧版在隔离期间对旧内置存储的修改由新版重新读取；对同一条记录的新旧并发编辑、删除与重建采用版本戳/墓碑和三方合并，无法可靠判定的冲突保留两份并提示，不能静默覆盖。队列目前只有一个旧格式且保存字段白名单，新版必须设计独立插件队列快照以及与旧队列的合并规则；下载索引/文件和选择/绑定等也各需独立隔离与一致性事务，不能只隔离收藏。实际旧版可能覆盖其自身字段、旧队列或缺文件下载索引；在没有事先隔离的历史版本上无法保证无损。备份不是自动合并，恢复前需验证它与降级期间用户编辑的关系。实现前需对每类存储定义原子性、冲突与回滚，包括进程崩溃及空间不足。未知或已卸载来源展示已有标题和不可用状态，不发起网易云请求；重新安装可恢复解析。禁止迁移期间运行两个版本并发写相同文件的假设未验证；需锁/单写者协议或显式排除。

## 决策 3：能力与动态 registry

每个插件实例由宿主适配为 Provider，接口仍以 `SearchCapability`、`PlaybackCapability`、`LyricsCapability` 等为能力边界；按握手结果构造仅实现对应接口的适配对象，或先演进 registry 为显式类型化能力查询。单个实现所有接口但只声称部分能力会误导现有 `is Capability` 检查；manifest 声明只是上限，握手及实现不符时拒绝启用该能力，下载独立判断。处理超时、插件死亡、分页游标及结构无效结果，提供有限尺寸的标准模型。宿主不把内置账号/session 给插件。

应用和播放服务共享一个权威插件目录持久状态，原子发布不可变 registry 快照 `(generation, providers)`；注册时检测内置/插件 ID 冲突。安装、启用、禁用、更新、卸载在验证与持久化成功后递增 generation；UI 订阅可观察快照，替换 `remember` 固定 registry；聚合遍历快照而非枚举。播放 runtime/resolver 必须获取同代快照并刷新：禁止新调用进入已禁用实例，取消或丢弃旧代 in-flight 结果，清除相关 URL/headers 缓存及请求去重；generation 计入键或在提交时校验。若当前歌曲已得到可用流，明确选择继续至切曲还是停止；建议禁用/卸载停止新解析，当前流由用户操作停止，安全撤销则停止并清理相关播放。Media3 字节缓存与 URL 缓存不同，需按身份/版本命名空间及私有响应策略处理，不能误删其他源缓存；失效后仍不能复用已撤销的凭据。跨进程时需 IPC 广播、重连及单调代数，不能假设进程内 StateFlow 会同步服务；服务重启从持久目录重建。实施需覆盖竞态和服务生命周期。

## 决策 4：运行时、安全边界和网络

现有 LX QuickJS 位于宿主进程：其线程与异步期限不能阻断同步死循环，也没有已验证的堆上限、强制终止或隔离。新插件不直接复用该信任边界。候选方案是在 Android 隔离服务进程内运行 QuickJS，宿主经有界、版本化 IPC 提供少量能力；进程隔离提供系统进程/UID 边界，宿主实施截止时间后可终止工作进程，恢复其他插件不应依赖受损实例。QuickJS 中断、内存限制及 wrapper 是否可用仍需源码核验和设备实测；进程死亡仍可能导致请求失败，内核/引擎漏洞和资源耗尽不能完全排除。每插件单独进程或共享进程的资源开销、API 24 可行性及进程重启频率待压测；未完成隔离和验证前不应称其安全沙箱或向不可信插件开放。

无文件、反射、任意系统 API 或宿主账户桥；仅暴露经过类型、大小、调用次数与时间限制的消息、计时器和宿主网络代理。插件自带凭据也可能外传，日志不得记录令牌、完整授权 URL 或敏感头；进程、IPC 和崩溃信息均视为不可信输入。插件不能提供原生库、DEX 或宿主执行代码。进程隔离不等于网络代理安全，也不自动验证媒体 URL。

网络代理设计为默认拒绝，manifest 声明域名/方法，宿主验证 HTTP(S)、端口、请求头、配额、超时、请求和响应大小；每次跳转重新检查目标和授权，禁止回环、私网、链路本地等地址，包括 IPv4/IPv6、映射地址及 DNS 重绑定，连接实际 IP 与校验绑定；代理、重定向及 TLS 主机名验证须明确并测试。是否允许局域网自托管属于待设计的单独授权策略，默认拒绝。`RestrictedHttpClient` 当前不提供上述完整防护。插件返回的媒体、封面、歌词 URL 及 headers 经过同一策略或安全的受控代理后才交给 Media3/图片/下载；否则会绕过网络控制。返回值禁止 `file:`、`content:` 和任意 intent，限制 header 与重定向，不暴露内置 cookie；签名 URL 到期和范围请求需兼容。网络访问不可避免地向获准服务器暴露请求数据，域名白名单不是防数据外传的证明。

## 决策 5：包与信任

候选 `.melox-plugin` 为 ZIP：根目录 `manifest.json`、JS 入口及静态资源，manifest 含 schema/API 范围、稳定 ID、版本、入口、能力、网络域名和包内容哈希；不含本地文件路径或宿主秘密。导入前限制压缩/解压大小、文件数量、嵌套和比率，拒绝绝对路径、`..`、重复路径、链接及编码歧义，在私有临时目录验证后原子安装。明确规范化签名内容和文件哈希；签名仅证明持有密钥及内容完整，不证明插件可信或授权合法。首次信任、未签名包策略、密钥轮换、撤销、版本回滚与分发机制尚未决定；未解决前不得自动更新或静默覆盖同 ID。包 API 版本不兼容则保留数据但禁用插件。

## 实施顺序与验收门槛

1. 固化旧版序列化、identity 和补源基线，针对每种存储准备真实旧版本 fixture；先设计隔离与降级合并并做崩溃恢复测试，再接入新来源。`PluginLegacyCompatibilityTest` 是当前行为特征测试，包含有意暴露的损失；它不是新系统应维持的行为，新存储实现后要保留旧 codec fixture，同时另测无损新契约。
2. 演进身份与存储：内置 ID、不同来源同资源、Unicode/URI、缺失/禁用/卸载/重装、嵌套未知字段；旧版读—改其他项—写—升级，逐字节比较隔离 payload，验证下载文件、队列及冲突合并。需要真实旧版二进制/数据目录升级降级测试，单元测试不等价。
3. registry 与能力：搜索分页、声明与接口不一致、无播放/歌词/下载、启停/更新并发、服务重启、正在播放和缓存代数；回归内置及 LX 顺序。歌词绑定、自动匹配和 AutoSync 切曲、音频/模型更新、跨源 key 碰撞单独测试。
4. 实现受控进程与网络之前，以设备测试验证同步死循环强杀、内存压力、IPC 大小、native 崩溃及进程重连；针对 DNS、IPv4/IPv6、代理、跳转、媒体 URL、限流、压缩炸弹和恶意 ZIP 建立负面用例。上述是发布门槛，不是已通过结果。

未决项：发布者命名注册与密钥信任、具体可迁移的旧版文件与冲突 UX、媒体代理与缓存开销、QuickJS wrapper 限制、隔离服务在各支持设备上的可用性、插件账户授权和局域网权限。以上未解决前不得承诺完整安全或任意旧版本降级无损。

插件认证补充要求及现有账号系统的源码审计见 [11-authentication.md](11-authentication.md)。认证是可选能力，须按具体操作声明登录要求；账号与凭据按插件 ID 和账号 ID 隔离且与插件版本解耦。该文记录的是设计约束，尚未实现。
